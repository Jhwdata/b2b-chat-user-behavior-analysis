# B2B Chat 사용자 행동 분석

> B2B 협업 플랫폼의 사용자 행동 데이터를 분석해  
> 신규 사용자의 핵심 활성 행동과 Retention 관련 이벤트를 탐색한 프로젝트입니다.

## 1. 프로젝트 개요

- **프로젝트명**: B2B Chat 사용자 행동 분석
- **형태**: 4인 팀 프로젝트
- **주제**: B2B 협업 플랫폼 사용자 행동 분석
- **분석 대상**: Slack과 유사한 B2B 협업/커뮤니케이션 서비스
- **사용 데이터**: Amplitude B2B Chat 이벤트 데이터
- **분석 및 시각화 도구**: Amplitude
- **목표**: 신규 사용자의 핵심 행동을 정의하고, Retention과 관련된 이탈 구간을 확인

이 프로젝트는 B2B Chat 서비스의 사용자 행동 데이터를 바탕으로,  
신규 사용자가 어떤 행동을 했을 때 서비스의 핵심 가치를 경험하고  
지속 사용으로 이어지는지 분석한 프로젝트입니다.

---

## 2. 문제 정의

B2B 협업 플랫폼은 가입자 수보다  
사용자가 실제 협업 기능을 경험하고 계속 사용하는지가 더 중요합니다.

이번 프로젝트에서는 다음 질문을 중심으로 분석을 진행했습니다.

1. 신규 사용자는 가입 이후 어떤 경로로 주요 기능에 도달하는가?
2. 사용자 활성도와 관련이 높은 이벤트는 무엇인가?
3. Retention을 예측할 수 있는 핵심 행동은 무엇인가?
4. 제품 개선을 위해 어떤 흐름을 강화해야 하는가?

이를 위해 사용자 여정을 먼저 확인하고,  
아하모먼트를 정의한 뒤 가설 검정을 진행했습니다.

---

## 3. 담당 역할

이 프로젝트에서 저는 **아하모먼트 설정과 가설 검정**을 담당했습니다.

주요 역할은 다음과 같습니다.

- 사용자 활성도와 관련이 높은 이벤트 탐색
- 아하모먼트 기준 설정
- 신규 사용자 기준 핵심 행동 정의
- 가설 검정 1~4 수행
- 퍼널 및 전환 흐름 해석
- Retention 관점의 개선 방향 도출

분석 과정에서는 사용자가 가입 이후 핵심 기능에 도달하기까지  
어느 구간에서 이탈이 발생하는지 확인하는 데 집중했습니다.

---

## 4. 데이터 및 분석 도구

이번 프로젝트는 **Amplitude B2B Chat 이벤트 데이터**를 활용했습니다.

사용자의 가입, 화면 진입, 채널 탐색, 메시지 전송, 이모지 반응 등  
서비스 내 주요 행동 이벤트를 기준으로 사용자 여정을 분석했습니다.

분석과 시각화는 모두 **Amplitude**에서 진행했으며,  
퍼널 분석, Retention 분석, 이벤트별 사용자 행동 비교를 통해  
신규 사용자의 핵심 활성 행동과 이탈 구간을 확인했습니다.

---

## 5. 분석 설계

### 5-1. 사용자 여정 분석

먼저 신규 사용자가 가입 이후 어떤 흐름으로 서비스를 사용하는지 확인했습니다.

분석에 활용한 주요 이벤트는 다음과 같습니다.

- User Sign Up
- Welcome
- Main Landing Screen
- Activate Account
- Search Channels
- Search Contacts
- Send Message
- Receive Push Notification
- React with Emoji
- End Session

특히 다음 두 퍼널을 비교했습니다.

- `User Sign Up → Send Message`
- `User Sign Up → Main Landing Screen → Send Message`

두 퍼널의 전환율은 모두 **54.5%**로 동일했고,  
퍼널 완료까지 걸린 시간 분포도 유사했습니다.

이를 통해 신규 사용자는 메시지를 보내기 전  
대부분 `Main Landing Screen`을 거친다는 점을 확인했습니다.

---

### 5-2. 아하모먼트 설정

아하모먼트는 사용자가 서비스의 핵심 가치를 경험했다고 볼 수 있는 행동으로 정의했습니다.

먼저 사용자 활성도와 상관관계가 높은 이벤트를 확인했습니다.

- Main Landing Screen
- Send Message
- Receive Push Notification
- Search Contacts
- React with Emoji

이 중 `Send Message`가 B2B 협업 서비스의 핵심 행동에 가장 가깝다고 판단했습니다.

분석 결과, 신규 사용자가 가입 후 1주일 이내  
**메시지를 13회 이상 전송한 경우** 4 Week Retention과 관련성이 높게 나타났습니다.

해당 기준의 상관관계는 **0.446**이었습니다.

따라서 이번 프로젝트에서는 아하모먼트를 다음과 같이 정의했습니다.

> **신규 사용자가 가입 후 1주일 이내 메시지를 13회 이상 전송하는 것**

---

## 6. 핵심 수행 내용

### 6-1. 가설 검정

아하모먼트를 정의한 뒤,  
사용자가 메시지 전송 행동에 도달하기까지의 흐름을 확인했습니다.

분석에 사용한 가설은 다음과 같습니다.

| 가설 | 확인한 내용 |
|---|---|
| 계정 활성화를 완료한 사용자는 메시지 전송 확률이 높다 | 계정 활성화 이후 메시지 전송으로 이어지는 흐름을 확인 |
| 채널에 가입한 사용자는 메시지 전송 확률이 높다 | 채널 가입 사용자의 메시지 전송 가능성이 높게 나타남 |
| 채널을 만들고 초대까지 이어지는 경우가 적다 | 채널 생성 이후 초대 단계에서 이탈이 크게 발생 |
| 메시지 전송을 한 사용자는 Retention이 높다 | 메시지 전송 행동이 장기 사용과 관련된 핵심 행동으로 나타남 |

채널 가입 여부를 본 이유는  
채널에 가입한 사용자의 메시지 전송 비율이 높게 나타났기 때문입니다.

즉, 채널 가입을 유도하면 메시지 기능을 사용하는 사용자 비율도  
함께 높아질 수 있다고 판단했습니다.

하지만 전체 사용자 기준으로는 채널 가입 단계에서 이탈이 크게 발생했습니다.

협업 서비스에서는 보통 한 사용자가 채널을 만들고  
팀원을 초대해 함께 사용하는 흐름이 자연스럽다고 보았습니다.

따라서 채널 생성 이후 초대까지 이어지는 흐름을 추가로 확인했습니다.

분석 결과, 초대까지 이어진 사용자는 대부분 1~2시간 안에 빠르게 초대를 진행했습니다.  
이를 통해 초대할 사용자가 명확한 경우에는  
채널 생성 후 바로 협업 흐름으로 이어진다고 판단했습니다.

하지만 전체 사용자 기준으로는 채널 생성 이후 초대 단계에서 이탈이 크게 나타났습니다.  
이는 초대 과정에서 사용자가 어려움을 겪고 있거나,  
UX/UI 측면에서 불편함이 있을 가능성이 있다고 해석했습니다.

### 6-2. 첫 메시지 도달 시간 분석

메시지 전송을 핵심 행동으로 본 뒤,  
사용자가 첫 메시지를 보내기까지 걸리는 시간도 확인했습니다.

| 구분 | 소요 시간 |
|---|---:|
| 전체 사용자 기준 첫 메시지 전송까지 걸린 시간 | 약 1시간 35분 |
| 신규 사용자 기준 첫 메시지 전송까지 걸린 시간 | 약 3시간 21분 |
| 전체 사용자 기준 첫 메시지 이후 재전송까지 걸린 시간 | 약 38분 |
| 신규 사용자 기준 첫 메시지 이후 재전송까지 걸린 시간 | 약 4시간 18분 |

신규 사용자는 전체 사용자보다 첫 메시지를 보내기까지 더 긴 시간이 걸렸습니다.

이는 신규 사용자가 서비스 구조를 이해하고,  
메시지를 보낼 상황을 찾는 데 시간이 필요하다는 의미로 해석했습니다.

## 7. 핵심 결과 및 액션 제안

| 핵심 결과 | 액션 제안 |
|---|---|
| 가입 후 1주일 이내 메시지 13회 이상 전송이 Retention과 관련성이 높게 나타남 | 첫 메시지 작성 가이드와 예시 메시지 템플릿 제공 |
| `Send Message`가 서비스의 핵심 행동으로 나타남 | 메시지 작성과 대화 참여를 쉽게 만드는 온보딩 설계 |
| 채널 가입 및 초대 과정에서 이탈이 발생 | 추천 채널 안내, 초대 링크 복사, 이메일 초대 기능 강화 |
| 신규 사용자는 첫 메시지까지 더 많은 시간이 필요 | 가입 직후 메시지 전송을 유도하는 UX 제공 |

이번 분석을 통해 B2B Chat 서비스의 핵심 사용 맥락은  
채널 탐색이나 기능 사용 자체보다 **메시지를 주고받는 과정**에 있다고 판단했습니다.

따라서 신규 사용자가 빠르게 첫 메시지를 보내고,  
채널과 초대 흐름을 통해 팀 단위 사용으로 이어지도록 만드는 것이 중요하다고 보았습니다.

---

## 8. 배운 점

이번 프로젝트를 통해 사용자 행동 분석에서는  
단순히 많이 발생한 이벤트보다 **제품의 핵심 가치와 연결되는 행동을 정의하는 것**이 중요하다는 점을 배웠습니다.

사용자 여정, 이벤트 간 상관관계, Retention 기준을 함께 보면서  
`Send Message`를 핵심 행동으로 판단했고,  
이를 바탕으로 아하모먼트를 정의할 수 있었습니다.

또한 가설 검정을 진행하면서  
분석 결과를 수치로만 보는 것이 아니라,  
퍼널 안에서 사용자가 어디서 이탈하는지와 제품 구조를 함께 보는 것이 중요하다는 점을 느꼈습니다.
